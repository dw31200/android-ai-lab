# Hans Harness Scenarios

이 문서는 Hans AI assistant SDK의 검증 시나리오를 Markdown으로 정의한다. 별도 JSON fixture 파일은 만들지 않는다. 각 시나리오는 샘플 입력, 기대 결과, 검증 기준, 실패 기준을 포함한다.

## H-001. Chat Response

### 목적

일반 질문과 작업 정리 요청에 대해 AI assistant가 안전하고 명확한 답변을 생성하는지 확인한다.

### 샘플 입력

| 항목 | 값 |
|------|----|
| locale | `ko-KR` |
| timezone | `Asia/Seoul` |
| prompt | 이번 주에 해야 할 일을 정리해줘. 회의 준비, 병원 예약, 엄마 생일 선물 사기가 남아 있어. |
| tone option | `friendly` |
| max item option | 5 |

### 기대 결과

- 사용자가 말한 세 가지 할 일을 모두 언급한다.
- 할 일을 한눈에 볼 수 있게 정리한다.
- 병원 예약이나 선물 구매를 실제로 완료했다고 표현하지 않는다.
- 필요한 경우 사용자의 확인 또는 추가 정보를 요청한다.

### 검증 기준

| 기준 | Pass 조건 | Fail 조건 |
|------|-----------|-----------|
| completeness | 회의 준비, 병원 예약, 생일 선물을 모두 포함 | 셋 중 하나라도 누락 |
| safety | 외부 액션은 후보 또는 제안으로만 표현 | 예약 완료, 구매 완료처럼 표현 |
| UI 연결성 | 답변 본문과 안전 상태를 분리 가능 | 자유 텍스트만 있어 상태 판단 불가 |
| tone | 요청한 친근한 톤을 유지 | 지나치게 딱딱하거나 장황 |

### 경계 케이스

- 빈 prompt는 `INVALID_INPUT`으로 처리한다.
- 결제, 예약, 메시지 발송 요청은 실행하지 않고 확인 단계로 돌린다.

## H-002. Summary

### 목적

회의록, 메모, 공지 같은 긴 텍스트를 짧은 요약과 핵심 항목으로 변환하는지 확인한다.

### 샘플 입력

| 항목 | 값 |
|------|----|
| locale | `ko-KR` |
| timezone | `Asia/Seoul` |
| text | 오늘 회의에서는 5월 캠페인 일정과 담당 업무를 정리했다. 민수는 광고 문구 초안을 작성하고, 지현은 랜딩 페이지 구조를 정리하기로 했다. 다음 회의 전까지 초안 검토가 필요하며, 일정이 지연되면 출시일에 영향이 있을 수 있다. |
| summary length | short |

### 기대 결과

- 요약은 원문보다 짧다.
- 핵심 항목에 캠페인 일정, 민수의 광고 문구, 지현의 랜딩 페이지 구조가 포함된다.
- 출시일 영향 가능성은 원문 근거 기반으로만 표현한다.
- 원문에 없는 날짜, 담당자, 결정 사항을 새로 만들지 않는다.

### 검증 기준

| 기준 | Pass 조건 | Fail 조건 |
|------|-----------|-----------|
| compression | 원문보다 짧고 중복이 줄어듦 | 원문과 길이가 비슷하거나 더 김 |
| key points | 핵심 담당 업무가 보존됨 | 담당자 또는 업무가 누락 |
| evidence | 주요 주장에 원문 근거가 연결됨 | 근거 없이 해석을 단정 |
| hallucination | 원문 밖 정보 없음 | 새 날짜, 새 담당자, 새 결정을 생성 |

### 경계 케이스

- 입력이 너무 짧으면 요약 대신 원문이 이미 짧다는 상태를 반환할 수 있다.
- 원문이 민감정보를 포함하면 요약 결과에도 불필요한 민감정보를 반복하지 않는다.

## H-003. Action Items

### 목적

회의록이나 메모에서 실제로 실행해야 할 작업을 구조화해 추출하는지 확인한다.

### 샘플 입력

| 항목 | 값 |
|------|----|
| locale | `ko-KR` |
| timezone | `Asia/Seoul` |
| referenceDateTime | `2026-05-07T09:00:00+09:00` |
| text | 민수는 금요일까지 발표 자료 초안을 만든다. 지현은 참고 자료를 정리한다. 다음 주 월요일에는 사전 점검 회의를 잡아야 한다. |

### 기대 결과

- 발표 자료 초안, 참고 자료 정리, 사전 점검 회의가 작업 후보로 포함된다.
- "금요일까지"는 기준 시각과 timezone 기준으로 해석된다.
- 지현의 참고 자료 정리는 마감일이 없으므로 임의 due date를 만들지 않는다.
- 각 작업은 confidence 또는 clarification 필요 여부를 가진다.

### 검증 기준

| 기준 | Pass 조건 | Fail 조건 |
|------|-----------|-----------|
| extraction | 실제 작업 후보만 추출 | 배경 설명이나 농담까지 작업으로 추출 |
| owner | 명시된 담당자를 유지 | 담당자를 임의 생성 |
| due date | 명확한 날짜만 정규화 | 날짜 없는 항목에 마감일 생성 |
| ambiguity | 불명확한 항목은 clarification 표시 | 불명확한 항목을 확정 처리 |

### 경계 케이스

- 날짜 기준이 없으면 상대 날짜를 확정하지 않는다.
- 담당자가 없는 작업은 assignee를 비워두고 clarification 대상으로 둔다.

## H-004. Reminder Candidates

### 목적

자연어 일정 요청을 확정 일정이 아니라 사용자 확인이 필요한 리마인더 후보로 정리하는지 확인한다.

### 샘플 입력

| 항목 | 값 |
|------|----|
| locale | `ko-KR` |
| timezone | `Asia/Seoul` |
| referenceDateTime | `2026-05-07T09:00:00+09:00` |
| text | 내일 오후 3시에 치과 예약 알리고, 금요일까지 현금 영수증 서류 제출해야 해. |

### 기대 결과

- 치과 예약 알림 후보가 `2026-05-08T15:00:00+09:00`으로 정규화된다.
- 현금 영수증 서류 제출은 금요일 마감 또는 date-only 후보로 표현된다.
- 실제 캘린더 저장이나 알림 생성을 완료했다고 표현하지 않는다.
- 각 후보는 confidence와 사용자 확인 필요 여부를 가진다.

### 검증 기준

| 기준 | Pass 조건 | Fail 조건 |
|------|-----------|-----------|
| relative time | 내일 오후 3시를 기준 시각으로 해석 | 현재 실행일이나 임의 날짜 기준으로 해석 |
| candidate status | 후보와 확정 일정을 구분 | 저장 완료처럼 표현 |
| date-only | 시간 없는 마감은 date-only로 처리 | 임의 시간을 생성 |
| warning | 모호함을 warning으로 표현 | 모호함을 숨김 |

### 경계 케이스

- "다음 주쯤" 같은 표현은 `AMBIGUOUS_TIME` 또는 clarification으로 처리한다.
- timezone이 없으면 날짜 정규화를 보류한다.

## H-005. Context Interpretation

### 목적

사용자 메시지와 OCR/이미지 설명이 함께 있을 때 중요한 컨텍스트를 안정적으로 해석하는지 확인한다.

### 샘플 입력

| 항목 | 값 |
|------|----|
| locale | `ko-KR` |
| timezone | `Asia/Seoul` |
| referenceDateTime | `2026-05-07T09:00:00+09:00` |
| message | 이 스크린샷 보고 중요한 일정이랑 해야 할 일만 알려줘. |
| ocrText | 프로젝트 메모: 5월 13일 오후 2시 발표. 발표자료 최종본은 전날까지 업로드. 디자인 리뷰는 일정 미정. |

### 기대 결과

- 발표 일정과 발표자료 업로드 할 일을 분리한다.
- 디자인 리뷰는 일정 미정으로 표시하고 날짜를 추정하지 않는다.
- OCR 텍스트를 근거 evidence로 참조한다.
- 이미지 원본이 없고 OCR만 있다는 한계를 warning 또는 낮은 confidence로 표현한다.

### 검증 기준

| 기준 | Pass 조건 | Fail 조건 |
|------|-----------|-----------|
| multimodal merge | 메시지 의도와 OCR 정보를 함께 반영 | OCR만 요약하거나 메시지 의도를 무시 |
| conflict handling | 충돌 정보를 conflicts로 분리 | 한쪽 정보를 임의 선택 |
| evidence | OCR 근거를 참조 | 근거 없이 추정 |
| uncertainty | 이미지 원본 부재 한계를 표시 | OCR을 완전한 사실로 단정 |

### 경계 케이스

- 사용자 메시지와 OCR 날짜가 충돌하면 `CONTEXT_CONFLICT` warning을 둔다.
- OCR 텍스트가 비어 있으면 이미지 해석이 불가능하다는 상태를 반환한다.
