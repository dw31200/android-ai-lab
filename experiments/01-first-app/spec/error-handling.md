# 에러 처리 명세

> 작성 규칙
> - 에러 코드: ERR-숫자 (예: ERR-001)
> - 모든 에러는 사용자에게 보여줄 메시지를 정의할 것
> - 에러 발생 시 복구 방법을 명시할 것

---

## 에러 유형 분류

| 유형 | 설명 | UI 처리 방식 |
|------|------|--------------|
| 입력 오류 | 사용자 입력 유효성 실패 | 인라인 에러 메시지 |
| 네트워크 오류 | 연결 실패, 타임아웃 | 스낵바 + 재시도 버튼 |
| 서버 오류 | API 4xx, 5xx | 스낵바 |
| 예기치 못한 오류 | 앱 내부 오류 | 다이얼로그 |

---

## 에러 코드 정의

| ID | 유형 | 발생 조건 | 사용자 메시지 | 복구 방법 |
|----|------|-----------|---------------|-----------|
| ERR-001 | 네트워크 | 인터넷 연결 없음 | "네트워크 연결을 확인해주세요" | 재시도 버튼 |
| ERR-002 | 서버 | API 500 응답 | "일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요" | 재시도 버튼 |
| ERR-003 | 서버 | API 401 응답 | "로그인이 필요합니다" | 로그인 화면으로 이동 |
| ERR-004 | 입력 | | | |

---

## 공통 에러 처리 구조

```kotlin
sealed class AppError {
    data class Network(val cause: Throwable) : AppError()
    data class Server(val code: Int, val message: String) : AppError()
    data class Unauthorized(val message: String) : AppError()
    data class Unknown(val cause: Throwable) : AppError()
}
```
